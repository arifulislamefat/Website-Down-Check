How this works

When you enter a URL, our server sends a real HTTP request directly to that site — the same kind of request a browser makes — and measures how long it takes to respond and what status code it returns. Because the check runs from our servers rather than your browser, it isn't affected by your own internet connection, VPN, or local network restrictions.

A site showing "down" here means our server couldn't get a successful response within 10 seconds. That's usually a strong signal something is actually wrong, though a single check can occasionally catch a temporary blip. If you're not sure, run the check again after a minute.

Common reasons a site might be down (and how to fix it)

  1. DNS not resolving. The domain isn't pointing anywhere valid. Check your nameservers and DNS records at your registrar or DNS provider, and confirm any recent changes have finished propagating.
  2. Hosting or server outage. Your hosting provider may be having downtime. Check their status page, or log into your server or hosting dashboard directly.
  3. Expired domain. If a domain isn't renewed in time, it stops resolving entirely. Check the expiration date in your registrar account.
  4. SSL certificate problems. An expired or misconfigured certificate can make browsers refuse to load the site. Renew or reissue the certificate through your host or certificate provider.
  5. Firewall or security rules blocking traffic. Overly strict firewall, rate-limiting, or bot-protection rules can accidentally block real visitors too. Review any recent changes to your firewall or security settings.
  6. Server overload. A sudden traffic spike can exhaust server resources. Check your server's CPU and memory usage, and consider caching or scaling up.
  7. Recent DNS or hosting migration. If you recently moved hosts or changed DNS providers, double-check the A and CNAME records actually point to the new server.
